# 과제 07: 인접 행렬과 인접 리스트의 성능 비교



## 1. 메모리 계산 기준

인접 행렬은 `MatrixGraph` 전체 크기를 `sizeof`로 측정하였다.
100 x 100 `int` 행렬과 정점 수, 간선 수를 포함한다.

인접 리스트는 `ListGraph` 구조체와 실제 연결 리스트 노드를 합산하였다.
무방향 간선 하나는 양쪽 정점의 리스트에 각각 저장되므로
간선 하나당 `Node` 두 개가 필요하다.

`malloc` 구현 내부의 관리 메타데이터는 제외하였다.

## 2. 비교 횟수 기준

- 인접 행렬에서 `(u, v)` 연결 확인: `matrix[u][v]` 한 칸 확인 = 1회
- 인접 리스트에서 연결 확인: `u`의 리스트에서 `v`를 찾을 때까지 방문한 노드 수
- 인접 행렬의 모든 이웃 확인: 행 하나의 100개 원소 확인 = 100회
- 인접 리스트의 모든 이웃 확인: 실제 리스트 노드 수 = 해당 정점의 차수
- 리스트 삭제는 무방향 간선의 양쪽 리스트에서 노드를 찾아야 하므로 두 탐색의 비교 횟수를 합산

삽입은 원래 존재하지 않는 간선, 삭제는 원래 존재하는 간선을 사용했고
행렬과 리스트에서 동일한 정점 쌍을 사용하였다.

## 3. 실제 측정 결과

| 경우 | 메모리 | 삽입 비교 | 삭제 비교 | 연결 확인 비교 | 인접 정점 비교 |
|---|---:|---:|---:|---:|---:|
| 희소 - 인접 행렬 | 40008 Bytes | 1 | 1 | 1 | 100 |
| 희소 - 인접 리스트 | 4008 Bytes | 1 | 6 | 4 | 0 |
| 밀집 - 인접 행렬 | 40008 Bytes | 1 | 1 | 1 | 100 |
| 밀집 - 인접 리스트 | 128808 Bytes | 75 | 117 | 62 | 77 |

## 4. 희소 그래프 분석

희소 그래프에서는 실제 간선이 100개뿐이다.
하지만 인접 행렬은 간선 수와 관계없이 100 x 100 공간을 항상 사용한다.

샘플 실행에서 희소 그래프의 메모리는

- 인접 행렬: 40008 Bytes
- 인접 리스트: 4008 Bytes

였다.

인접 리스트는 실제 존재하는 간선만 노드로 저장하므로
희소 그래프에서 공간 효율이 매우 높다.

특정 정점의 인접 정점을 모두 찾는 경우에도
행렬은 항상 100개 항목을 확인하지만,
리스트는 실제 차수만큼만 노드를 확인한다.

샘플에서는

- 인접 행렬: 100회
- 인접 리스트: 0회

였다.

따라서 희소 그래프에서는 메모리와 이웃 순회 측면에서
인접 리스트가 유리하다.

## 5. 밀집 그래프 분석

밀집 그래프는 가능한 4,950개 간선 중 4,000개를 가진다.
각 정점의 차수가 높기 때문에 인접 리스트에도 많은 노드가 필요하다.

샘플 실행에서 메모리는

- 인접 행렬: 40008 Bytes
- 인접 리스트: 128808 Bytes

였다.

희소 그래프에 비해 인접 리스트의 메모리 사용량이 크게 증가하였다.

연결 여부 확인에서는 행렬이 직접 인덱싱으로 1회 비교만 필요하지만,
리스트는 해당 정점의 리스트를 순차 검색해야 한다.

샘플에서는 밀집 그래프의 연결 확인 비교가

- 인접 행렬: 1회
- 인접 리스트: 62회

였다.

밀집 그래프에서는 각 리스트 길이가 길어지므로
연결 여부 확인, 삽입 전 중복 확인, 삭제 위치 탐색 비용이 커진다.

## 6. 삽입과 삭제

인접 행렬은 간선의 존재 여부를 한 칸에서 직접 확인할 수 있어
삽입과 삭제 모두 기본적으로 1회의 비교로 판단할 수 있다.

반면 인접 리스트의 삽입은 중복 여부를 확인하기 위해
한 정점의 리스트를 탐색해야 한다.

샘플 삽입 비교 횟수:

- 희소 리스트: 1회
- 밀집 리스트: 75회

삭제는 양쪽 정점의 리스트에서 서로를 찾아야 한다.

샘플 삭제 비교 횟수:

- 희소 리스트: 6회
- 밀집 리스트: 117회

밀집 그래프에서는 정점의 차수가 높기 때문에
리스트 기반 삽입/삭제의 검색 비용이 증가하는 경향이 있다.

## 7. 어떤 표현이 적절한가

### 인접 행렬

다음 상황에 적합하다.

- 그래프가 밀집되어 있음
- 두 정점의 직접 연결 여부를 매우 자주 확인함
- 빠른 간선 존재 여부 확인이 중요함
- `O(V^2)` 메모리를 감당할 수 있음

연결 여부 확인은 `O(1)`이다.

### 인접 리스트

다음 상황에 적합하다.

- 그래프가 희소함
- 실제 간선만 저장하여 메모리를 절약해야 함
- 특정 정점의 모든 인접 정점을 자주 순회함
- 정점 수에 비해 간선 수가 적음

공간 복잡도는 일반적으로 `O(V + E)`이다.

## 8. 결론

실험 결과, 그래프의 밀도가 표현 방법의 효율을 크게 바꾼다는 것을 확인했다.

희소 그래프에서는 인접 리스트가 실제 간선만 저장하기 때문에
메모리를 크게 절약하고, 한 정점의 이웃 전체를 찾을 때도
실제 차수만큼만 방문하면 된다.

반면 인접 행렬은 그래프 밀도와 관계없이
두 정점의 연결 여부를 항상 한 번의 직접 접근으로 확인할 수 있다.
따라서 연결 확인이 빈번하거나 그래프가 밀집된 경우에 유리하다.

결론적으로 **희소 그래프에는 인접 리스트,
밀집 그래프 또는 연결 여부 확인이 매우 빈번한 경우에는 인접 행렬**이
더 적합하다고 판단할 수 있다.
