# 과제 08: 최소 비용 신장 트리 알고리즘 비교

## 1. 그래프 연결성 보장

단순히 임의 간선만 생성하면 연결 그래프가 아닐 수 있다. 따라서 먼저 정점 50개의 순서를 무작위로 섞고, 각 새 정점을 앞에서 이미 연결된 정점 중 하나와 연결한다. 이 과정으로 49개의 간선을 가진 spanning tree가 먼저 만들어진다.

그 후 이미 존재하지 않는 정점 쌍만 선택하여 간선을 추가하므로 self-loop와 중복 간선도 발생하지 않는다. 따라서 프로그램을 여러 번 실행해도 그래프는 항상 연결되어 있고 MST는 반드시 49개의 간선을 갖는다.

## 2. 실행시간 측정 기준

그래프 생성과 출력은 측정에서 제외하였다. 각 MST 함수 내부에서 실제 알고리즘이 시작되는 시점부터 MST 계산이 끝나는 시점까지 C11 `timespec_get()`으로 측정하였다. 단위는 마이크로초(us)이다.

Kruskal의 측정에는 인접 리스트에서 간선 추출, 정렬, Union-Find 초기화, MST 선택이 포함된다. Prim의 측정에는 보조 배열 초기화, 최소 key 정점 선택, 행렬 검사와 key 갱신, MST 결과 구성이 포함된다.

실행시간은 CPU 상태와 운영체제 스케줄링에 따라 실행할 때마다 달라질 수 있다.

## 3. 실제 실행 결과

seed `20261013`으로 실행한 결과는 다음과 같다.

| Case | 방법 | MST 간선 수 | MST 비용 | 메모리 | 실행시간 |
|---|---|---:|---:|---:|---:|
| 1 | 희소 + List + Kruskal | 49 | 15206 | 5796 Bytes | 27.952 us |
| 2 | 밀집 + List + Kruskal | 49 | 2454 | 27796 Bytes | 64.877 us |
| 3 | 희소 + Matrix + Prim | 49 | 15206 | 11196 Bytes | 14.181 us |
| 4 | 밀집 + Matrix + Prim | 49 | 2454 | 11196 Bytes | 27.792 us |

희소 그래프에서는 Kruskal과 Prim의 MST 비용이 모두 15206이었고, 밀집 그래프에서는 모두 2454였다. 따라서 동일한 그래프에 대해 두 알고리즘이 같은 최소 비용을 계산했음을 확인하였다.

선택되는 간선의 조합은 동일 가중치가 존재할 경우 서로 다를 수 있지만, MST의 전체 비용은 동일해야 한다.

## 4. 희소 그래프 분석

희소 그래프는 정점 50개에 간선이 100개뿐이다. 인접 리스트는 실제 존재하는 간선에 대해서만 노드를 저장하기 때문에 공간 효율이 높다.

이번 실행에서 메모리는 다음과 같았다.

- 인접 리스트 + Kruskal: 5796 Bytes
- 인접 행렬 + Prim: 11196 Bytes

즉, 희소 그래프에서는 인접 리스트 기반 Kruskal이 메모리를 훨씬 적게 사용하였다.

Kruskal은 100개의 간선을 정렬해야 하지만 E가 작기 때문에 정렬 대상 자체가 많지 않다. Prim은 실제 간선 수와 관계없이 50 x 50 행렬을 유지하고, 각 반복에서 정점 수를 기준으로 검사한다.

실행시간은 이번 한 번의 측정에서 Kruskal 27.952 us, Prim 14.181 us로 Prim이 더 짧게 나왔다. 다만 정점 수가 50으로 작고 실행시간 자체가 매우 짧기 때문에 마이크로초 단위의 값은 실행 환경의 영향을 크게 받을 수 있다. 따라서 희소 그래프에서는 단일 실행시간보다 인접 리스트의 메모리 절약과 `E log E` 특성을 함께 보는 것이 중요하다.

## 5. 밀집 그래프 분석

밀집 그래프는 정점 50개에 간선 600개를 가진다. 간선 수가 증가하면 인접 리스트에서는 간선 하나마다 두 개의 ListNode가 필요하고, Kruskal의 정렬용 Edge 배열도 커진다.

이번 실행의 메모리는 다음과 같았다.

- 인접 리스트 + Kruskal: 27796 Bytes
- 인접 행렬 + Prim: 11196 Bytes

밀집 그래프에서는 오히려 인접 행렬 + Prim이 더 적은 메모리를 사용하였다. 인접 행렬은 간선 수가 100개든 600개든 정점 수가 50으로 같으면 크기가 변하지 않지만, 인접 리스트는 E에 비례하여 커지기 때문이다.

실행시간은 Kruskal 64.877 us, Prim 27.792 us였다. Kruskal은 600개의 간선을 추출하고 정렬해야 하므로 희소 그래프보다 시간이 늘었다. Prim은 `O(V^2)` 구조이므로 V가 동일한 상황에서는 간선 수 증가의 영향을 상대적으로 덜 받는다.

## 6. Kruskal과 Prim의 특성 차이

### Kruskal

장점:

- 간선 중심으로 동작한다.
- 희소 그래프에서 처리할 간선 수가 적다.
- 인접 리스트와 잘 맞는다.
- Union-Find를 이용해 cycle 검사를 효율적으로 수행할 수 있다.

주요 비용:

- 인접 리스트에서 간선 수집
- 간선 정렬
- Union-Find 연산

시간 복잡도는 일반적으로 `O(E log E)`이다.

### Prim

장점:

- 하나의 정점에서 시작해 MST를 확장한다.
- 인접 행렬과 함께 사용할 때 구현이 단순하다.
- 밀집 그래프에서 행렬 기반 처리가 자연스럽다.

이번 구현의 주요 비용은 최소 key 정점 선택과 행렬의 행 검사이며 시간 복잡도는 `O(V^2)`이다.

## 7. 그래프 밀도가 미치는 영향

인접 리스트 + Kruskal은 간선 수 E가 커질수록 다음 항목이 모두 증가한다.

- ListNode 수
- 정렬용 Edge 배열 크기
- 정렬해야 하는 간선 수

따라서 메모리와 실행시간이 E 증가의 영향을 직접 받는다.

반면 인접 행렬 + Prim은 행렬 크기가 `V x V`로 고정되어 있다. 이번 과제처럼 V=50이 고정되어 있다면 희소/밀집 여부와 관계없이 행렬 크기는 동일하고, Prim의 기본 반복량도 주로 V에 의해 결정된다.

따라서 그래프가 밀집될수록 인접 행렬 + Prim의 상대적 장점이 커질 수 있다.

## 8. 결론

모든 경우에서 MST 간선 수는 정확히 49개였고, 동일한 그래프에 대해 Kruskal과 Prim의 전체 MST 비용도 일치하였다.

희소 그래프에서는 실제 간선만 저장하는 인접 리스트의 공간 효율이 크기 때문에 인접 리스트 + Kruskal 조합이 자연스럽다.

반면 밀집 그래프에서는 인접 리스트가 많은 간선 노드를 저장해야 하고 Kruskal이 정렬해야 하는 간선 수도 증가한다. 인접 행렬 + Prim은 V가 고정되어 있으면 메모리와 반복 구조가 간선 수 증가의 영향을 상대적으로 덜 받는다.

따라서 일반적으로 **희소 그래프에는 인접 리스트 + Kruskal, 밀집 그래프에는 인접 행렬 + Prim**이 적합한 선택이라고 볼 수 있다. 다만 실제 실행시간은 입력 크기, 구현 방식, 하드웨어와 운영체제에 따라 달라질 수 있으므로 시간 복잡도와 메모리 구조를 함께 고려해야 한다.
