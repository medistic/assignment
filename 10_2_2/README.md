# 과제 10: 정렬 알고리즘의 성능 및 안정성 비교

## 1. 컴파일 및 실행

GCC 기준:

```bash
gcc -O2 -std=c11 -Wall -Wextra -Wpedantic main.c -o assignment10
```

기본 실행:

```bash
./assignment10
```

기본 실행은 과제 명세대로 무작위 실험을 100회 수행한다.

동일한 결과를 재현하려면 seed를 지정할 수 있다.

```bash
./assignment10 20261022
```

두 번째 인자로 무작위 반복 횟수를 지정할 수도 있다.

```bash
./assignment10 20261022 1
```

이 기능은 코드 검증 시간을 줄이기 위한 것이며, 인자를 생략하면 기본값은 100회이다.

---

## 2. 난수 생성

`key1`과 `key2`는 각각 0~1,000,000 범위에서 독립적으로 생성한다.

일부 C 구현, 특히 Windows 환경에서는 `RAND_MAX`가 상대적으로 작을 수 있으므로
한 번의 `rand()` 결과만 사용하는 대신 두 번의 결과를 결합하여
0~1,000,000 전체 범위를 사용할 수 있도록 하였다.

동일한 데이터에서 같은 키가 여러 번 발생하는 것은 허용한다.

---

## 3. 비교 횟수와 이동 횟수의 기준

### 숫자 비교

정렬 순서를 결정하기 위해 두 데이터의 `key1`을 비교할 때만 1회로 계산한다.
반복문의 인덱스 비교나 종료 조건은 포함하지 않는다.

### 데이터 이동

`Data` 구조체 전체가 다른 저장 위치 또는 임시 변수로 복사될 때 1회로 계산한다.

예를 들어 두 데이터를 교환하는 경우:

```c
temp = data[i];
data[i] = data[j];
data[j] = temp;
```

이므로 이동 횟수는 3회이다.

삽입 정렬에서는 다음 연산도 각각 1회 이동으로 센다.

- 현재 데이터를 임시 변수에 저장
- 기존 데이터를 오른쪽으로 한 칸 이동
- 현재 데이터를 최종 위치에 저장

원본 배열을 실험용 배열로 `memcpy`하는 과정과 시험 데이터 생성/변형 과정은
측정값에 포함하지 않았다.

## 4. 무작위 데이터 100회 실험 결과

- 데이터 수: 10,000개
- 반복 횟수: 100회
- seed: `20261022`

| 알고리즘 | 총 비교 횟수 | 평균 비교 횟수 | 총 이동 횟수 | 평균 이동 횟수 |
|---|---:|---:|---:|---:|
| 선택 정렬 | 4,999,500,000 | 49,995,000.00 | 2,996,946 | 29,969.46 |
| 버블 정렬 | 4,999,500,000 | 49,995,000.00 | 7,497,320,871 | 74,973,208.71 |
| 버블 정렬(조기 종료) | 4,998,521,939 | 49,985,219.39 | 7,497,320,871 | 74,973,208.71 |
| 삽입 정렬(`>`) | 2,500,105,970 | 25,001,059.70 | 2,501,106,757 | 25,011,067.57 |

모든 100회 실험에서 네 알고리즘의 결과가 `key1` 기준 오름차순임을 확인하였다.

### 결과 분석

선택 정렬은 입력 상태와 관계없이 아직 정렬되지 않은 영역 전체에서 최솟값을 찾아야 한다.
따라서 10,000개 데이터에서는 한 번의 실행마다 비교 횟수가 항상

```text
10000 × 9999 / 2 = 49,995,000
```

회이다.

일반 버블 정렬 역시 조기 종료를 하지 않으므로 모든 pass를 수행하고,
비교 횟수는 선택 정렬과 같은 49,995,000회가 된다.

무작위 데이터에서 조기 종료 버블 정렬은 100회 전체 기준으로
일반 버블보다 978,061회 적게 비교하였다.
이는 전체 4,999,500,000회 중 약 **0.0196% 감소**에 불과하다.

무작위 데이터는 거의 마지막 pass까지 교환이 발생하기 때문에
조기 종료 조건의 효과가 매우 작게 나타났다.

삽입 정렬의 평균 비교 횟수는 약 25,001,060회로,
선택/일반 버블의 49,995,000회보다 약 절반 수준이었다.
무작위 입력에서 삽입 정렬은 현재 데이터보다 큰 앞쪽 원소만 이동시키므로
평균적으로 전체 앞부분의 약 절반 정도를 지나가는 특성이 나타난 것이다.

## 5. 버블 정렬 조기 종료 분석

조기 종료 버블 정렬은 한 pass 동안 교환이 한 번도 일어나지 않으면
이미 정렬이 완료되었다고 판단하고 종료한다.

### 무작위 데이터

- 일반 버블 총 비교: 4,999,500,000회
- 조기 종료 총 비교: 4,998,521,939회
- 감소량: 978,061회
- 감소율: 약 0.0196%

따라서 무작위 데이터에서는 조기 종료의 효과가 거의 없었다.

### 이미 정렬된 데이터

- 일반 버블: 49,995,000회
- 조기 종료 버블: 9,999회

조기 종료 버블은 첫 번째 pass에서 교환이 한 번도 발생하지 않으므로 즉시 종료하였다.
비교 횟수가 약 **99.98% 감소**하였다.

### 역순 데이터

- 일반 버블: 49,995,000회
- 조기 종료 버블: 49,995,000회

역순 데이터는 매 pass에서 계속 교환이 발생하므로 조기 종료의 이점이 전혀 없었다.

### 일부 정렬된 데이터

- 일반 버블: 49,995,000회
- 조기 종료 버블: 49,971,995회

일부만 교란된 데이터라도 멀리 이동해야 하는 원소가 있으면 마지막 단계에 가까워질 때까지
교환이 계속 발생할 수 있다. 따라서 이번 부분 정렬 방식에서는 조기 종료의 비교 감소가
23,005회, 약 0.046%에 그쳤다.

즉, 조기 종료는 단순히 "대부분 정렬되어 있다"는 사실만으로 항상 큰 이득을 주는 것이 아니라,
남아 있는 역전이 몇 번의 pass 안에 해소될 수 있는지에도 영향을 받는다.

## 6. 안정성 검증 방법

안정성을 확실하게 확인하기 위해 `key1`이 중복되는 별도의 작은 데이터를 사용하였다.

```text
(Key1, Key2, OriginalIndex)
(5,100,0) (3,200,1) (5,300,2) (2,400,3)
(3,500,4) (5,600,5) (2,700,6) (3,800,7)
```

정렬 후 같은 `key1`을 갖는 데이터들의 `original_index`가 증가하는 순서를 그대로 유지하는지 검사하였다.

### 실제 결과

| 알고리즘 | 안정성 |
|---|---|
| 선택 정렬 | Unstable |
| 버블 정렬 | Stable |
| 삽입 정렬 (`>`) | Stable |
| 삽입 정렬 (`>=`) | Unstable |

### 선택 정렬

선택 정렬에서는 가장 작은 원소를 찾은 뒤 현재 위치의 원소와 직접 교환한다.
이 교환 때문에 같은 키를 가진 데이터가 서로를 건너뛸 수 있다.

실제 결과에서 `key1 = 3`인 데이터의 원래 순서는

```text
idx=1 -> idx=4 -> idx=7
```

이지만 선택 정렬 후에는

```text
idx=4 -> idx=1 -> idx=7
```

이 되어 상대 순서가 바뀌었다.
따라서 이 구현의 선택 정렬은 불안정 정렬이다.

### 버블 정렬

버블 정렬은

```c
data[j].key1 > data[j + 1].key1
```

일 때만 교환한다.
키가 같은 두 데이터는 서로 교환하지 않으므로 원래 상대 순서가 유지되었다.
따라서 안정 정렬이다.

### 삽입 정렬에서 `>` 사용

이동 조건이

```c
data[j].key1 > current.key1
```

이면 키가 같은 데이터는 이동하지 않는다.
따라서 같은 키의 기존 데이터 뒤에 새 데이터가 들어가고 상대 순서가 유지된다.
실험 결과 Stable이었다.

### 삽입 정렬에서 `>=` 사용

조건을

```c
data[j].key1 >= current.key1
```

로 변경하면 같은 키의 기존 데이터도 오른쪽으로 이동한다.
새로 처리하는 동일 키 데이터가 기존 동일 키 데이터 앞으로 들어가므로 순서가 뒤집힐 수 있다.

실제 `key1 = 5` 그룹은 원래

```text
idx=0 -> idx=2 -> idx=5
```

였지만 `>=` 삽입 정렬 후

```text
idx=5 -> idx=2 -> idx=0
```

으로 뒤집혔다.
따라서 `>=` 버전은 불안정 정렬이다.

## 7. 입력 상태별 성능 결과

### 7-1. 이미 정렬된 데이터

| 알고리즘 | 비교 횟수 | 이동 횟수 |
|---|---:|---:|
| 선택 정렬 | 49,995,000 | 0 |
| 버블 정렬 | 49,995,000 | 0 |
| 버블 정렬(조기 종료) | 9,999 | 0 |
| 삽입 정렬(`>`) | 9,999 | 19,998 |

선택 정렬은 데이터가 이미 정렬되어 있다는 사실을 활용하지 못한다.
매 위치마다 남은 영역 전체를 계속 확인하므로 비교 횟수가 그대로이다.

일반 버블 정렬 역시 모든 pass를 강제로 수행하므로 비교 횟수가 감소하지 않는다.
반면 조기 종료 버블은 첫 pass 하나만 수행하여 9,999회 만에 종료한다.

삽입 정렬도 각 데이터가 바로 제자리에 있다는 것을 한 번의 key 비교로 확인하므로
비교 횟수가 9,999회뿐이다.
다만 과제의 이동 정의에 따라 각 단계에서 `current`를 임시 변수에 저장하는 1회와
같은 위치에 다시 대입하는 1회를 모두 이동으로 계산하여 총 19,998회가 측정되었다.

---

## 7-2. 역순 데이터

| 알고리즘 | 비교 횟수 | 이동 횟수 |
|---|---:|---:|
| 선택 정렬 | 49,995,000 | 15,081 |
| 버블 정렬 | 49,995,000 | 149,984,823 |
| 버블 정렬(조기 종료) | 49,995,000 | 149,984,823 |
| 삽입 정렬(`>`) | 49,995,000 | 50,014,939 |

역순 입력은 버블 정렬과 삽입 정렬에 가장 불리한 형태이다.
작은 값들이 배열의 앞쪽으로 긴 거리를 이동해야 하기 때문이다.

버블 정렬은 인접 원소를 하나씩 교환하므로 데이터 이동 횟수가 매우 크게 증가했다.
교환 한 번마다 3회의 데이터 이동이 발생하기 때문에 약 1억 5천만 회의 이동이 측정되었다.

삽입 정렬도 많은 원소를 한 칸씩 이동시켜야 하므로 비교와 이동이 크게 증가한다.

선택 정렬은 비교 횟수는 동일하게 많지만 한 위치당 최대 한 번만 swap하므로
이동 횟수는 버블 정렬보다 훨씬 적었다.

---

## 7-3. 일부 정렬된 데이터

부분 정렬 데이터는 다음 방법으로 만들었다.

1. 하나의 무작위 원본 데이터 10,000개를 준비한다.
2. 첫 번째 키 기준으로 완전히 정렬한다.
3. 서로 다른 두 위치를 무작위로 선택하여 교환하는 작업을 100번 수행한다.

10,000개 데이터에 대해 100번의 위치 교환을 수행하므로
"데이터 수의 1%에 해당하는 횟수만큼 무작위 교란"을 가한 형태이다.

이 준비 과정에서 발생하는 비교 및 이동은 측정값에 포함하지 않았다.


### 실제 결과

| 알고리즘 | 비교 횟수 | 이동 횟수 |
|---|---:|---:|
| 선택 정렬 | 49,995,000 | 303 |
| 버블 정렬 | 49,995,000 | 1,977,315 |
| 버블 정렬(조기 종료) | 49,971,995 | 1,977,315 |
| 삽입 정렬(`>`) | 669,104 | 679,103 |

선택 정렬의 비교 횟수는 여전히 49,995,000회이다.
입력이 거의 정렬되어 있어도 남은 영역에서 최솟값을 찾는 과정을 생략하지 않기 때문이다.

일반 버블 역시 모든 pass를 수행하므로 비교 횟수는 변하지 않았다.

조기 종료 버블은 일부 감소했지만 이번 교란 방식에서는 멀리 떨어진 위치끼리 swap될 수 있어서
완전히 정렬된 경우만큼 큰 개선은 발생하지 않았다.

반면 삽입 정렬은 이미 대부분의 데이터가 올바른 위치 근처에 있기 때문에
이동해야 할 앞쪽 원소가 매우 적었다.
비교 횟수는 49,995,000회에서 669,104회로 약 **98.66% 감소**하였다.

이 결과는 삽입 정렬이 부분 정렬 데이터에 매우 적합하다는 특징을 잘 보여준다.

## 8. 세 알고리즘의 특성 비교

### 선택 정렬

- 비교 횟수: 입력 상태와 거의 무관하게 `O(n^2)`
- swap 횟수: 최대 `n-1`회 수준
- 데이터 이동 횟수는 상대적으로 적음
- 일반적인 swap 기반 구현은 불안정 정렬
- 이미 정렬된 데이터의 비교 횟수도 줄지 않음

이번 실험에서도 무작위, 정렬, 역순, 부분 정렬 모두
비교 횟수가 49,995,000회로 동일하였다.

### 버블 정렬

- 인접 원소를 계속 swap하므로 이동 비용이 큼
- 일반 버전은 입력 상태가 좋아도 모든 pass 수행
- `>`로만 교환하면 안정 정렬
- 조기 종료를 넣으면 이미 정렬된 입력에서 매우 빠르게 종료 가능

무작위/역순 데이터에서는 조기 종료 효과가 거의 없었지만,
완전히 정렬된 데이터에서는 49,995,000회에서 9,999회로 크게 감소하였다.

### 삽입 정렬

- 현재 원소를 이미 정렬된 앞부분에 삽입
- 무작위 데이터에서는 평균적으로 선택/버블보다 비교가 적음
- 이미 정렬 또는 부분 정렬 입력에서는 매우 효율적
- 역순 데이터에서는 `O(n^2)`의 최악 성능
- `>` 조건에서는 안정 정렬
- `>=` 조건에서는 불안정 정렬

이번 부분 정렬 실험에서 비교 횟수가 669,104회에 그쳐
다른 세 방법보다 초기 정렬 상태를 가장 효과적으로 활용하였다.

## 9. 결론

이번 실험을 통해 세 `O(n^2)` 정렬 알고리즘도
입력 데이터의 초기 상태와 구현 세부 조건에 따라 실제 비교/이동 횟수가 크게 달라진다는 것을 확인하였다.

선택 정렬은 입력 상태의 영향을 거의 받지 않고 항상 많은 비교를 수행했지만,
swap 횟수가 제한되어 있어 이동 횟수는 상대적으로 작았다.

일반 버블 정렬은 비교 횟수가 크고 인접 swap을 반복하기 때문에 데이터 이동도 매우 많았다.
조기 종료 조건은 이미 정렬된 데이터에서는 매우 큰 효과가 있었지만,
무작위나 역순 데이터에서는 효과가 거의 없었다.

삽입 정렬은 무작위 데이터에서도 선택/버블보다 평균 비교 횟수가 작았고,
이미 정렬된 데이터와 부분 정렬 데이터에서는 성능이 크게 개선되었다.
특히 부분 정렬 입력에서 669,104회의 비교만 수행하여 초기 정렬 상태를 가장 잘 활용하였다.

안정성 측면에서는 버블 정렬과 `>` 조건을 사용한 삽입 정렬이 안정 정렬이었고,
일반 swap 기반 선택 정렬은 불안정하였다.
또한 삽입 정렬의 비교 조건을 `>`에서 `>=`로 단 한 글자 변경하는 것만으로도
동일 키 데이터가 서로 이동하면서 안정성이 깨지는 것을 실제 시험 데이터로 확인하였다.

따라서 정렬 알고리즘을 선택할 때에는 단순한 Big-O 시간복잡도뿐 아니라
**입력의 초기 정렬 정도, 데이터 이동 비용, 조기 종료 가능성, 안정성 요구사항**까지 함께 고려해야 한다.
