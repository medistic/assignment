# 과제 11: 삽입 정렬과 쉘 정렬의 성능 비교

## 1. 컴파일 및 실행

```bash
gcc -std=c11 -O2 -Wall -Wextra -Wpedantic main.c -o assignment11
```

일반 실행:

```bash
./assignment11
```

동일한 난수 데이터를 재현하려면 seed를 지정한다.

```bash
./assignment11 20261027
```

---

## 2. 비교 횟수 측정 기준

반복문의 인덱스 검사나 종료 조건은 세지 않고, 실제 데이터 값끼리 비교한 경우만 1회로 계산하였다.

삽입 정렬에서는 현재 삽입할 값 `current`와 앞쪽 값 `data[j]`를 비교하는 `data[j] > current`를 수행할 때마다 비교 횟수를 1 증가시킨다.

쉘 정렬에서는 각 gap에 대해 gap 간격의 삽입 정렬을 수행하며, `data[j-gap] > current`를 수행할 때마다 비교 횟수를 1 증가시킨다.

---

## 3. 실제 측정 결과

seed `20261027`의 결과는 다음과 같다.

| 데이터 크기 | 삽입 정렬 | Shell Original | Shell Knuth |
|---:|---:|---:|---:|
| 1,000 | 249,348 | 14,840 | 14,109 |
| 2,000 | 1,011,088 | 35,597 | 31,918 |
| 4,000 | 4,041,041 | 86,268 | 80,248 |
| 8,000 | 16,025,564 | 208,135 | 178,795 |
| 16,000 | 63,628,973 | 492,134 | 397,370 |
| 20,000 | 99,242,936 | 631,805 | 551,507 |

모든 데이터 크기에서 세 정렬 결과가 오름차순인지 다시 검사했으며 모두 `Sorted Verification : Yes`가 출력되었다. 추가로 여러 다른 seed에서도 같은 검증을 수행하였다.

---

## 4. 데이터 크기 증가에 따른 비교 횟수 변화

n이 1,000에서 20,000으로 20배 증가했을 때 비교 횟수는 다음과 같이 증가하였다.

- 삽입 정렬: 249,348 → 99,242,936, 약 **398배** 증가
- Shell Original: 14,840 → 631,805, 약 **42.6배** 증가
- Shell Knuth: 14,109 → 551,507, 약 **39.1배** 증가

삽입 정렬은 무작위 데이터에서 현재 원소보다 큰 앞쪽 원소를 한 칸씩 지나가며 위치를 찾아야 한다. 데이터가 커질수록 이러한 작업이 급격하게 증가하며, 실험에서도 데이터 크기의 증가보다 비교 횟수가 훨씬 빠르게 증가했다.

쉘 정렬은 큰 gap을 이용해 멀리 떨어진 원소를 먼저 이동시킨다. 이 과정을 거치면 마지막 gap=1 단계에 도달하기 전에 배열이 이미 상당히 정돈된다. 따라서 마지막 삽입 정렬 단계의 작업량이 크게 줄고, 전체 비교 횟수도 일반 삽입 정렬보다 훨씬 작다.

---

## 5. 삽입 정렬과 쉘 정렬의 성능 차이

n=20,000에서 측정된 비교 횟수는 다음과 같다.

- 삽입 정렬: **99,242,936회**
- Shell Original: **631,805회**
- Shell Knuth: **551,507회**

따라서 같은 입력에서 삽입 정렬은 Shell Original보다 약 **157배**, Shell Knuth보다 약 **180배** 많은 비교를 수행했다.

이 차이는 쉘 정렬이 멀리 떨어진 원소를 초기에 이동시킬 수 있기 때문에 발생한다. 삽입 정렬은 원소를 한 칸씩만 이동시키므로 멀리 떨어진 역전 관계를 해결하는 데 많은 비교가 필요하지만, 쉘 정렬은 큰 gap 단계에서 이러한 큰 순서 오류를 빠르게 줄인다.

---

## 6. Original Sequence와 Knuth Sequence 비교

이번 실험에서는 모든 데이터 크기에서 Knuth 수열이 Original 수열보다 적은 비교를 수행했다.

- n=1,000: Original 14,840 / Knuth 14,109
- n=2,000: Original 35,597 / Knuth 31,918
- n=4,000: Original 86,268 / Knuth 80,248
- n=8,000: Original 208,135 / Knuth 178,795
- n=16,000: Original 492,134 / Knuth 397,370
- n=20,000: Original 631,805 / Knuth 551,507

특히 n=20,000에서는 Knuth 수열이 Original 수열보다 **80,298회**, 약 **12.7%** 적은 비교를 수행했다.

Shell의 기본 수열은 단순히 절반씩 줄어드는 구조라 gap들이 서로 강한 배수 관계를 가진다. 이 때문에 이전 단계에서 비교된 원소 관계와 비슷한 위치 관계가 다음 단계에서도 반복될 수 있다.

Knuth 수열은 1, 4, 13, 40, 121처럼 다른 형태의 간격을 사용한다. 이로 인해 원소들이 여러 거리 관계에서 섞여 비교되며, 큰 역전 관계가 더 효율적으로 제거될 수 있다. 이번 무작위 데이터 실험에서는 이러한 차이가 Knuth 수열의 더 적은 비교 횟수로 나타났다.

단, 어떤 한 번의 입력에 대해서도 Knuth가 반드시 항상 더 적은 비교를 보인다고 일반화할 수는 없다. 실제 비교 횟수는 입력 배열의 배치와 gap 수열의 조합에 영향을 받는다.

---

## 7. Gap 수열이 성능에 영향을 미치는 이유

쉘 정렬의 마지막 단계는 결국 gap=1인 삽입 정렬이다. 따라서 전체 성능을 결정하는 핵심은 **gap=1이 되기 전에 배열을 얼마나 잘 정리해 두는가**이다.

좋지 않은 gap 수열은 특정 거리 관계의 원소를 반복적으로 비교하거나, 일부 역전 관계를 마지막 단계까지 남겨 둘 수 있다. 그러면 gap=1 단계에서 많은 비교가 다시 필요해진다.

반대로 효과적인 gap 수열은 큰 위치 오류를 초기에 제거하고 여러 거리의 원소를 단계적으로 정리한다. 마지막 단계에 들어갔을 때 배열이 거의 정렬된 상태가 되므로 삽입 정렬이 매우 적은 비교만으로 끝난다.

따라서 쉘 정렬은 같은 알고리즘이라도 gap 수열에 따라 실제 성능 차이가 발생한다.

---

## 8. 결론

실험 결과 데이터 크기가 증가할수록 삽입 정렬의 비교 횟수는 매우 빠르게 증가한 반면, 두 쉘 정렬은 훨씬 완만하게 증가하였다.

n=20,000에서는 삽입 정렬이 약 9,924만 회를 비교한 반면 Shell Original은 약 63만 회, Shell Knuth는 약 55만 회만 비교했다. 따라서 큰 무작위 데이터에서는 쉘 정렬이 일반 삽입 정렬보다 훨씬 효율적이었다.

또한 이번 실험에서는 모든 데이터 크기에서 Knuth 수열이 Original 수열보다 적은 비교를 수행했다. 이는 gap 선택이 중간 단계에서 배열을 정돈하는 방식과 마지막 gap=1 단계의 작업량에 직접 영향을 준다는 것을 보여준다.
