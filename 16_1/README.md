# 과제 16: 순차 탐색과 이진 탐색의 성능 비교

## 1. 프로그램 구성 및 실행

- `main.c`: CSV 입력, 학생 정보 저장, 직접 구현한 퀵 정렬, 순차·이진 탐색, 비교 횟수 측정 및 결과 검증
- `students.csv`: 제공된 `dataset_id_ascending (1) (1).csv`의 이름만 바꾼 사본 (내용 변경 없음)
- `sample_output.txt`: 실제 CSV를 사용하여 실행한 결과
- `compile.txt`: GCC 컴파일 명령

```sh
gcc -std=c11 -O2 -Wall -Wextra -Wpedantic main.c -o assignment16
./assignment16
./assignment16 students.csv Dakota
```

Windows(MinGW GCC, PowerShell)에서는 `gcc -std=c11 -O2 -Wall -Wextra -Wpedantic main.c -o assignment16.exe`로 컴파일하고 ` .\assignment16.exe students.csv Dakota`로 실행한다. 원본 파일명을 그대로 사용하려면 ` .\assignment16.exe "dataset_id_ascending (1) (1).csv" Dakota`로 실행한다. 이름을 생략하면 동명이인이 가장 많은 이름 중 이름순으로 가장 앞에 있는 이름을 출력한다. CSV는 제공된 영문 헤더 순서와 UTF-8 또는 ASCII 인코딩을 사용하며, 한 학생의 레코드는 한 줄에 있어야 한다. 이름은 최대 255바이트이며 학번은 문자열로 보관하여 앞의 0도 유지한다. 쉼표가 포함된 인용 필드와 이중 따옴표 이스케이프를 처리한다.

## 2. 데이터와 탐색 구현

제공된 CSV에 학생 32,033명의 학번, 이름, 성별 및 세 과목 점수가 저장되어 있다. 서로 다른 이름은 20,735개로 이름 중복이 실제로 존재한다. 총점은 세 점수의 합으로 계산한다. 기본 예시 검색은 `Dakota`이며, 같은 이름인 학생 9명의 학번, 이름, 성별, 각 점수와 총점을 모두 출력한다. 검색 결과는 원본 배열 순서로 표시한다.

순차 탐색은 원본 배열을 정렬하지 않고 처음부터 끝까지 검사한다. 동명이인이 나중에 나타날 수 있으므로 처음 일치한 원소에서 종료하지 않는다. 따라서 존재하지 않는 이름을 검색하더라도 한 번의 검색에 정확히 32,033회 비교한다.

퀵 정렬은 원본 배열의 복사본만 정렬한다. 피벗 선택은 Median-of-Three이며, 같은 이름이 많은 입력에서 불필요한 분할을 줄이기 위해 피벗보다 작은 값, 같은 값, 큰 값의 세 구간으로 나누는 3-way partition을 사용했다. 작은 구간을 재귀 호출하고 큰 구간은 반복문으로 처리한다. 정렬 기준은 이름 하나이며 학번이나 점수는 정렬에 사용하지 않는다. 이름 비교는 대소문자를 구분하는 C `strcmp`를 공통으로 사용한다. UTF-8에서는 바이트 사전식 순서를 사용한다.

이진 탐색은 lower bound를 이용하여 검색 이름 이상인 첫 위치를 찾은 다음, 해당 위치부터 이름이 일치하는 학생을 모두 탐색한다. 첫 번째 불일치 이름을 검사하는 경우도 비교 횟수에 포함한다. 정렬 전후 전체 학생 정보와 검색 결과 집합을 원래 행 번호를 사용하여 검증하므로 동명이인의 결과 순서가 달라도 학생이 누락되거나 추가되면 오류를 검출한다.

## 3. 비교 횟수 측정 기준

이름 비교 함수 `name_cmp`가 `strcmp`를 한 번 호출할 때마다 카운터를 1 증가시킨다. 퀵 정렬의 중앙값 선택 및 분할, 순차 탐색, 이진 탐색의 위치 결정 및 중복 이름 확인에서 수행하는 모든 이름 비교가 포함된다. CSV 읽기, 점수 합산, 배열 복사, 실험 준비, 검증 및 출력은 포함하지 않는다. 검증용 `strcmp`도 알고리즘 비교 횟수에는 포함하지 않는다.

순차 탐색 총비용은 K번의 순차 탐색 비교 횟수 합계이다. 퀵 정렬과 이진 탐색의 총비용은 최초 퀵 정렬의 513,962회에 K번 이진 탐색 비교 횟수를 더한 값이다. 각 K에 정렬 비용을 한 번만 반영한다. 예시 학생 검색 비용은 별도로 출력하고 K 실험에는 합산하지 않는다.

## 4. 검색 횟수 K의 설정과 실험 설계

이 실험의 목적은 단순히 두 탐색 알고리즘의 탐색 속도를 비교하는 것이 아니라, 최초 정렬에 필요한 비용까지 포함했을 때 검색을 몇 번 수행해야 정렬된 배열을 사용하는 것이 이득인지 알아보는 것이다. 따라서 검색 횟수가 적은 구간은 촘촘히 측정하고, 검색 횟수가 많은 구간은 넓은 간격으로 결과를 비교하였다.

| 구분 | 검색 횟수 K | 설정 이유 |
|---|---|---|
| 시작값 | 1 | 한 번만 검색할 때 정렬 비용이 얼마나 부담이 되는지 확인 |
| 초기 구간 | 1~30, 1회씩 증가 | 두 방식의 총 비교 횟수가 처음 역전되는 정확한 정수 K를 확인 |
| 중간 및 장기 구간 | 50, 100, 200, 500, 1,000 | 검색이 반복될수록 초기 정렬 비용의 부담이 얼마나 감소하는지 확인 |
| 최댓값 | 1,000 | 한 번 검색하는 경우와 충분히 반복하는 경우를 비교하고, 3,203만 회의 순차 비교까지 실험할 수 있도록 설정 |

중간 및 장기 구간의 출력 간격은 각각 20, 50, 100, 300, 500회로 점차 넓혔다. 이는 역전점을 확인한 이후에는 매번의 작은 차이보다 누적 비용의 증가 추세를 파악하는 것이 중요하기 때문이다. 단, 실제 프로그램은 K=1부터 1,000까지 한 번씩 검색하면서 누적 비교 횟수를 계산한다. 일부 K의 결과만 표에 출력할 뿐 중간 검색을 생략하지 않는다.

검색 목록은 고정 시드 `20261126`으로 생성하였다. 매 5번째 검색에는 CSV에 존재하지 않는 것으로 미리 확인한 이름을 사용하고, 나머지는 원본 배열에서 무작위로 학생을 선택하여 그 이름을 사용하였다. 총 1,000회 중 800회는 존재하는 이름, 200회는 존재하지 않는 이름을 검색한다. 학생 단위로 표본을 뽑으므로 동명이인이 많은 이름은 선택될 가능성이 상대적으로 높고, 동일 이름이 여러 번 검색될 수도 있다. 두 탐색은 완전히 동일한 검색 이름과 순서를 사용하며, K가 증가할 때 기존 검색을 유지한 채 새 검색을 추가한다. 이 조건으로 검색 대상 차이에 의한 오차를 방지하였다.

## 5. 최초 퀵 정렬 비용과 K별 실제 측정 결과

### 5.1. 최초 퀵 정렬에 필요한 비교 횟수

CSV에는 전체 학생 32,033명과 서로 다른 이름 20,735개가 존재한다. 원본 배열의 복사본을 이름 기준으로 퀵 정렬한 결과, 최초 정렬에서 **513,962회**의 이름 비교가 발생하였다. 이 수치는 Median-of-Three 피벗 선택에 사용한 `strcmp` 호출과 3-way partition에서 피벗과 데이터를 비교한 모든 `strcmp` 호출을 합한 실제 측정값이다.

Median-of-Three는 극단적인 값이 피벗이 될 가능성을 낮추며, 3-way partition은 피벗과 이름이 같은 데이터를 한 구간으로 모아 해당 구간을 다시 정렬하지 않는다. 이는 동명이인이 존재하는 이번 데이터에 적합한 방식이다. 다만 피벗 선택 자체에도 비교 비용이 발생하며, 513,962회는 이 구현과 현재 CSV의 입력 순서 및 이름 분포에서 얻은 값이다.

순차 탐색은 한 번에 32,033회 비교하므로, 최초 정렬 비용만으로도 순차 탐색 약 16.04회에 해당한다. 따라서 검색 횟수가 매우 적다면, 이진 탐색 자체가 효율적이더라도 처음부터 정렬하는 방식의 총비용이 더 클 수 있다.

## 6. K 증가에 따른 총 비교 횟수 및 역전점 분석

### 6.1. 두 방식의 증가율 차이

학생 수를 N=32,033, 최초 정렬 비용을 S=513,962, i번째 이진 탐색의 이름 비교 횟수를 b_i라고 하면, 총 비교 횟수는 다음과 같다.

```text
순차 탐색:         C_seq(K) = 32,033 × K
퀵 정렬 + 이진 탐색: C_bin(K) = 513,962 + (b_1 + ... + b_K)
```

순차 탐색은 동명이인을 모두 확인해야 하므로 첫 번째 일치 학생을 발견해도 종료할 수 없다. 이름이 존재하지 않을 때도 모든 원소를 확인한다. 따라서 검색 대상과 관계없이 검색을 한 번 추가할 때마다 비교 횟수가 정확히 32,033회 증가하며, K에 대해 일정한 기울기의 직선으로 증가한다.

반면 이진 탐색은 이름순으로 정렬된 배열에서 `lower_bound` 방식으로 탐색 범위를 절반씩 줄여 첫 일치 후보의 위치를 찾는다. 이후 같은 이름인 원소만 순차적으로 확인한다. N=32,033이므로 위치를 찾기 위한 이진 탐색은 최대 약 15회의 이름 비교가 필요하다. 여기에 일치한 학생 수 및 첫 불일치 확인 비용이 추가된다. 예를 들어 `Dakota`는 동명이인 9명이 존재하며 실제 예시 검색의 비교 횟수는 순차 탐색 32,033회, 이진 탐색 25회였다.

1,000회 실험에서 이진 탐색만의 누적 비교 횟수는 17,334회였으므로 평균은 17.334회이다. 순차 탐색 한 번의 비용은 이진 탐색 한 번의 평균 비용보다 약 1,848배 크다. 다만 이진 탐색 쪽에는 고정된 초기 정렬 비용이 있으므로 이 비율이 총비용에 즉시 적용되는 것은 아니다.

| 검색 구간 | 순차 탐색 증가량 | 퀵 정렬 + 이진 탐색 증가량 |
|---|---:|---:|
| K=10 → 100 | 2,882,970 | 1,579 |
| K=100 → 1,000 | 28,829,700 | 15,577 |

두 경우 모두 검색 횟수가 10배가 되면 순차 탐색 총비용도 정확히 10배가 된다. 그러나 퀵 정렬을 포함한 방식은 K=100에서 K=1,000으로 증가해도 총비용이 515,719회에서 531,296회로 약 3.02%만 증가한다. 이진 탐색에서 검색 자체의 비용이 초기 정렬 비용에 비해 매우 작기 때문이다.

### 6.2. 역전 구간: K=16과 K=17 사이

| 항목 | K=16 | K=17 |
|---|---:|---:|
| 순차 탐색 누적 비교 | 512,528 | 544,561 |
| 최초 퀵 정렬 | 513,962 | 513,962 |
| 이진 탐색 누적 비교 | 279 | 296 |
| 퀵 정렬 + 이진 탐색 누적 비교 | 514,241 | 514,258 |
| 더 적은 비교 횟수 | 순차 (1,713회 절약) | 퀵+이진 (30,303회 절약) |

K=16에서 K=17로 넘어갈 때 순차 탐색은 32,033회가 추가되지만, 이진 탐색은 17회만 추가된다. 따라서 두 방법의 총비용 차이가 한 번의 검색으로 32,016회만큼 변화하면서 우열이 역전된다.

정렬 비용을 S, 한 번의 평균 이진 탐색 비교 횟수를 b라고 놓으면, 두 방식의 총비용이 같아지는 지점을 다음과 같이 추정할 수 있다.

```text
N × K = S + b × K
(N - b) × K = S
K = S / (N - b)
  = 513,962 / (32,033 - 17.334)
  ≈ 16.0535
```

검색 횟수는 정수이므로 이 모델에서는 K=17부터 퀵 정렬과 이진 탐색이 유리할 것으로 예상된다. 실제 누적 비교 횟수에서도 K=16까지 순차 탐색이 더 적고 K=17부터 퀵 정렬과 이진 탐색이 더 적었다. 평균 비교 횟수로 계산한 값은 근사치이며, 정확한 역전점은 실제 누적 비교 횟수로 결정하였다.

### 6.3. 초기 정렬 비용의 분산(상각)

퀵 정렬과 이진 탐색의 검색 1회당 평균 총비용은 `513,962 / K + (누적 이진 탐색 비교 횟수 / K)`이다. 이 값은 검색을 반복할 때 최초 정렬 비용을 여러 번의 검색에 나누어 부담하는 효과를 보여준다.

| K | 순차 탐색 1회당 평균 | 퀵+이진 1회당 평균 (정렬 포함) | 정렬 비용의 1회당 부담 |
|---:|---:|---:|---:|
| 1 | 32,033.00 | 513,980.00 | 513,962.00 |
| 16 | 32,033.00 | 32,140.06 | 32,122.63 |
| 17 | 32,033.00 | 30,250.47 | 30,233.06 |
| 100 | 32,033.00 | 5,157.19 | 5,139.62 |
| 1,000 | 32,033.00 | 531.30 | 513.96 |

K=1일 때는 퀵 정렬과 이진 탐색의 총비용이 순차 탐색보다 약 16.05배 크다. 하지만 K=1,000에서는 초기 정렬을 포함하더라도 순차 탐색의 32,033,000회보다 31,501,704회 적은 531,296회만 비교한다. 이는 비교 횟수를 약 98.34% 줄인 것이며, 순차 탐색의 총비용이 약 60.29배 더 크다는 뜻이다. 검색을 많이 반복할수록 정렬을 한 번 수행하는 비용보다 이후의 검색 효율이 더 중요해진다.

## 7. 최초 정렬 비용을 고려한 장단점 및 결론

### 7.1. 시간 복잡도 및 자료구조 차이

| 항목 | 순차 탐색 | 퀵 정렬 + 이진 탐색 |
|---|---|---|
| 최초 준비 비용 | 정렬 불필요 | 퀵 정렬 평균 O(N log N), 최악 O(N²) |
| 검색 1회 | O(N) | O(log N + M) |
| K회 검색 총비용 | O(KN) | 평균 O(N log N + K log N + ΣM_i) |
| 동명이인 검색 | 전체 배열 검사 | 첫 위치를 찾고 연속된 일치 구간 검사 |
| 원본 배열 유지 | 별도 정렬 배열 불필요 | 현재 구현은 정렬용 학생 배열 복사본 O(N) 필요 |
| 데이터 갱신 | 정렬 상태 유지 불필요 | 정렬된 배열 유지에 삽입·삭제 이동 또는 재정렬 비용 발생 가능 |

M은 한 번의 검색에서 일치하는 학생의 수이며, ΣM_i는 K번의 검색에서 일치한 학생 수의 합이다. 이진 탐색의 검색 비용을 단순히 O(log N)이라고만 표현하면 동명이인 확인 비용이 누락되므로 이번 과제에서는 O(log N + M)으로 분석한다. 모든 학생의 이름이 같다면 이진 탐색도 결과를 모두 확인해야 하므로 탐색 이점이 작아질 수 있다.

### 7.2. 순차 탐색이 적합한 경우

검색 횟수가 적거나 학생 정보가 자주 변경되는 경우에는 순차 탐색이 유리할 수 있다. 초기 정렬과 별도의 정렬 복사본이 필요 없으며, 원본 배열에 데이터가 추가되거나 삭제되어도 이름 정렬 상태를 관리할 필요가 없다. 이번 실험에서는 K=1부터 K=16까지 실제 비교 횟수가 더 적었다. 특히 일회성 검색을 위해 513,962회의 이름 비교를 먼저 수행하는 것은 32,033회만 필요한 순차 탐색에 비해 비효율적이었다.

단점은 학생 수가 증가하거나 검색 요청이 많아질 때 전체 배열을 반복해서 확인해야 한다는 것이다. 이번 실험에서 K=1,000의 순차 탐색 비용이 3,203만 회 이상으로 증가한 원인도 여기에 있다.

### 7.3. 퀵 정렬 + 이진 탐색이 적합한 경우

학생 데이터가 일정 기간 유지되고 동일한 자료를 대상으로 검색이 반복되는 경우에는 한 번 정렬한 뒤 이진 탐색하는 방식이 유리하다. 초기 정렬 비용을 지불하고 나면 추가 검색에 필요한 비교 횟수가 매우 적다. 학사 정보의 이름 검색처럼 같은 목록을 여러 번 조회하는 상황에서는 초기 정렬을 매번 반복하지 않고 재사용할 수 있다.

단점은 정렬에 필요한 사전 처리와 현재 구현에서 원본 보존용 배열 복사본에 필요한 추가 메모리이다. 데이터가 자주 갱신되어 매번 정렬을 다시 해야 한다면 초기 정렬 비용이 여러 번 발생해 실험에서 확인한 이점이 감소할 수 있다. 이미 이름순으로 정렬된 입력을 이용할 수 있다면 정렬 비용이 사라져 이진 탐색은 더 이른 시점부터 유리해진다.

### 7.4. 결론 및 실험의 한계

이번 실험에서는 처음 16회까지 순차 탐색이 더 적은 비교를 수행했으나, 17회부터 최초 정렬 비용을 포함하더라도 퀵 정렬과 이진 탐색의 총 비교 횟수가 더 적었다. 이 차이는 순차 탐색의 검색당 비용이 O(N)인 반면 이진 탐색은 O(log N + M)이기 때문에 나타났다. 정렬의 필요성은 단순히 탐색 알고리즘의 복잡도만으로 판단하는 것이 아니라, 초기 정렬 비용과 예상 검색 횟수를 함께 고려해야 한다.

다만 17회라는 역전점은 현재 CSV의 학생 수, 이름 중복 분포, 입력 순서, 퀵 정렬 구현 및 고정 검색 목록에서 측정한 값이다. 본 실험은 이름 비교 횟수만 비교하였으며, 실제 실행시간의 배율을 측정한 것은 아니다. 문자열 길이, 데이터 복사, 메모리 접근과 캐시 등의 비용은 별도의 시간 실험에서 고려해야 한다. 또한 데이터 갱신 비용은 이번 실험에 포함하지 않았다.

## 8. 검증

GCC C11, `-O2 -Wall -Wextra -Wpedantic -Werror`로 컴파일하였다. 실제 CSV의 모든 정렬 레코드 및 1,000회 검색 결과 집합을 확인하였다. Dakota 및 Liam 검색 결과의 모든 점수와 총점은 CSV 원본과도 별도로 대조하였으며, 존재하지 않는 이름과 쉼표가 들어간 이름(인용 CSV 필드)을 포함한 별도 시험도 통과했다.
