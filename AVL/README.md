# 과제 - 06: 순차 탐색, 이진 탐색 트리와 AVL 트리의 성능 비교

## 1. 프로그램 개요

0부터 1000 사이의 정수를 정확히 100번 임의 생성하고, 같은 난수를 같은 순서로 다음 세 자료구조에 처리한다.

- 정수 배열(Array)
- 이진 탐색 트리(Binary Search Tree, BST)
- AVL 트리(AVL Tree)

동일한 값이 다시 생성되는 것은 허용하지만, 이미 저장된 값이면 중복으로 판단하여 새로 삽입하지 않는다. 따라서 100번의 생성이 끝난 뒤 세 자료구조에는 동일한 서로 다른 값들이 저장된다.

이후 0부터 1000 사이의 탐색 키 50개를 추가로 생성하여 배열에서는 순차 탐색, BST에서는 BST 탐색, AVL에서는 AVL 탐색을 수행하고 숫자 비교 횟수를 측정한다.

본 프로그램에서 숫자 비교 횟수는 **삽입하려는 값 또는 탐색 키와 실제 저장된 데이터 값을 비교한 횟수**만 의미한다. AVL의 높이 계산, balance factor 계산, 회전 여부 판단 및 회전 자체는 비교 횟수에 포함하지 않는다.

## 4. 비교 횟수 계산 기준

### 배열 생성

새 난수가 생성되면 현재 배열의 첫 번째 원소부터 차례로 비교한다. 같은 값을 찾으면 중복으로 판단하고 삽입하지 않으며, 끝까지 같은 값이 없으면 배열의 마지막에 삽입한다. 이 과정에서 저장된 배열 원소와 새 값을 비교할 때마다 1회로 계산한다.

### BST 생성

루트부터 시작해 현재 노드와 새 값을 비교한다. 값이 같으면 중복으로 종료하고, 작으면 왼쪽, 크면 오른쪽으로 이동한다. 방문한 기존 노드 하나당 1회의 데이터 비교로 계산한다.

### AVL 생성

삽입 위치를 찾는 데이터 비교 방식은 BST와 동일하다. 삽입 뒤 균형을 복구하기 위한 높이 계산, balance factor 확인, LL/RR/LR/RL 회전 판단 및 회전 수행은 과제 명세에 따라 숫자 비교 횟수에 포함하지 않는다.

### 탐색

순차 탐색은 배열 원소 하나를 확인할 때마다 1회, BST와 AVL은 현재 노드 하나를 확인할 때마다 1회로 계산한다.

## 6. 생성 비용 비교

이번 실행에서 배열을 구성하는 동안 4,055회의 비교가 발생했다. 반면 BST는 625회, AVL은 515회였다.

배열에서는 새로운 값이 중복인지 확인하기 위해 현재 저장된 원소를 처음부터 순서대로 확인해야 한다. 새로운 값이 배열에 존재하지 않을 경우 현재 배열에 저장된 모든 원소와 비교해야 하므로, 저장된 값의 수가 커질수록 중복 확인 비용도 함께 증가한다.

BST와 AVL은 값의 대소 관계를 이용하여 한쪽 서브트리만 따라 내려가므로 매 삽입 시 전체 데이터를 확인할 필요가 없다. 따라서 이번 실험에서는 두 트리의 생성 과정에서 배열보다 훨씬 적은 데이터 비교가 발생했다.

AVL의 생성 비교 횟수 515회가 BST의 625회보다 작았던 이유는 AVL이 회전을 통해 높이를 낮게 유지했기 때문이다. 삽입 위치를 찾는 경로 자체가 일반 BST보다 짧아지는 경우가 많아 새 값과 기존 노드의 비교 횟수도 감소했다. 단, AVL의 회전과 높이 갱신 자체에는 추가 연산 비용이 존재하지만 이번 과제의 '숫자 비교 횟수'에는 포함하지 않았다.

## 7. BST와 AVL의 높이가 다른 이유

두 트리는 동일한 85개의 값을 같은 순서로 입력받았지만 최종 높이는 서로 달랐다.

- BST 높이: 11
- AVL 높이: 8

일반 BST는 이진 탐색 조건만 유지하며 트리의 균형을 조정하지 않는다. 따라서 값이 들어오는 순서에 따라 특정 방향의 서브트리가 길게 늘어날 수 있다.

AVL은 각 노드에서 왼쪽과 오른쪽 서브트리의 높이 차이를 관리하고, 균형이 깨질 경우 다음 회전을 수행한다.

- LL: 오른쪽 회전
- RR: 왼쪽 회전
- LR: 왼쪽 회전 후 오른쪽 회전
- RL: 오른쪽 회전 후 왼쪽 회전

이 회전 때문에 AVL은 일반 BST보다 높이가 작고 균형에 가까운 형태를 유지한다.

---

## 8. 트리 높이가 탐색 비교 횟수에 미치는 영향

트리 탐색은 루트부터 시작하여 한 번 비교할 때마다 왼쪽 또는 오른쪽 자식으로 한 단계씩 내려간다. 따라서 탐색에서 방문할 수 있는 노드의 최대 개수는 트리 높이의 영향을 직접 받는다.

이번 실행에서 BST 높이는 11, AVL 높이는 8이었다. 50회 탐색의 결과도 다음과 같이 나타났다.

- BST 총 비교 횟수: 371회, 평균 7.42회
- AVL 총 비교 횟수: 314회, 평균 6.28회

AVL의 높이가 더 낮았기 때문에 평균적으로 루트에서 탐색 종료 지점까지 더 짧은 경로를 이용할 수 있었고, 그 결과 BST보다 적은 비교 횟수가 발생했다.

다만 특정 탐색 키 하나만 보면 BST가 AVL보다 적은 비교를 할 수도 있다. 회전으로 인해 각 값의 위치가 달라지기 때문이다. 예를 들어 어떤 값이 일반 BST에서는 루트 가까이에 있고 AVL에서는 조금 더 아래에 있을 수 있다. 그러나 전체적으로 보면 AVL은 트리의 높이를 제한하므로 탐색 성능이 삽입 순서에 덜 민감하고 더 안정적이다.

## 9. 순차 탐색과 트리 탐색 비교

이번 실행에서 순차 탐색은 50회의 탐색에 총 3,890회의 비교, 평균 77.80회의 비교가 필요했다.

배열에는 85개의 값이 저장되어 있었기 때문에, 존재하지 않는 값을 찾을 때는 매번 85개의 원소를 전부 확인해야 한다. 이번 탐색에서는 성공이 7회뿐이었으므로 실패 탐색이 많았고, 이 때문에 순차 탐색의 평균 비교 횟수가 크게 증가했다.

반면 BST와 AVL은 대소 관계를 이용해 탐색 범위를 좁혔기 때문에 평균 비교 횟수가 각각 7.42회와 6.28회에 그쳤다.

따라서 같은 데이터를 여러 번 검색하는 상황에서는 단순 배열의 순차 탐색보다 트리 기반 탐색이 훨씬 적은 데이터 비교를 수행할 수 있음을 확인할 수 있었다.

## 10. 전체 성능 분석

### 배열

장점은 구조가 단순하고 최초 발생 순서를 그대로 유지한다는 점이다. 그러나 중복 확인과 탐색 모두 순차적으로 수행되므로 데이터 수가 증가할수록 비교 횟수가 크게 증가한다.

### BST

배열보다 적은 비교로 삽입 위치와 탐색 위치를 찾을 수 있다. 하지만 트리 균형을 보장하지 않으므로 삽입 순서가 좋지 않으면 높이가 크게 증가한다. 최악의 경우 트리가 연결 리스트와 비슷한 구조가 되어 탐색 비용이 O(n)에 가까워질 수 있다.

### AVL

BST의 탐색 규칙을 사용하면서 회전으로 균형을 유지한다. 따라서 높이가 O(log n) 수준으로 제한되어 삽입 위치 탐색과 검색 모두 안정적인 비교 횟수를 기대할 수 있다. 대신 높이 갱신과 회전 같은 추가 작업이 필요하므로 실제 CPU 연산량은 데이터 비교 횟수만으로 완전히 표현되지는 않는다.

이번 실험에서는 생성 비교 횟수와 탐색 비교 횟수 모두 AVL이 가장 작았고, AVL의 높이도 BST보다 낮았다. 이는 균형 유지가 실제 탐색 경로를 짧게 만들어 데이터 비교 횟수를 감소시킨 결과라고 볼 수 있다.

## 11. 결론

동일한 100개의 난수 생성 결과를 배열, BST, AVL에 적용한 결과 85개의 서로 다른 값이 저장되었고 15개는 중복으로 처리되었다.

생성 과정에서는 배열 4,055회, BST 625회, AVL 515회의 데이터 비교가 발생했다. 최종 높이는 BST 11, AVL 8이었다.

50회의 탐색에서는 순차 탐색이 평균 77.80회, BST가 7.42회, AVL이 6.28회의 비교를 수행했다. 따라서 이번 실험에서는 트리 구조를 사용함으로써 순차 탐색보다 비교 횟수가 크게 감소했고, AVL의 균형 유지로 BST보다도 더 낮은 평균 비교 횟수를 얻었다.

결과적으로 **트리에서 실제 탐색 성능은 저장된 데이터의 수뿐 아니라 트리의 높이와 균형 상태에 크게 영향을 받으며, AVL의 균형 유지가 탐색 성능을 안정적으로 만드는 핵심 요소**임을 확인할 수 있었다.
