

## 1. 실험 결과

실행 명령:

```bash
./bst_compare 20260929
```

측정 결과는 다음과 같다.

| 항목 | 결과 |
|---|---:|
| 저장 데이터 개수 | 100개 |
| 탐색 횟수 | 50회 |
| 탐색 성공 횟수 | 4회 |
| 순차 탐색 총 비교 횟수 | 4,813회 |
| 순차 탐색 평균 비교 횟수 | 96.26회 |
| BST 탐색 총 비교 횟수 | 413회 |
| BST 탐색 평균 비교 횟수 | 8.26회 |
| BST 생성 비교 횟수 | 612회 |
| BST 생성 + BST 탐색 비교 횟수 | 1,025회 |

## 2. 순차 탐색과 BST 탐색 성능 비교

50회의 탐색 과정에서 순차 탐색은 총 4,813회의 비교를 수행했지만,
BST 탐색은 총 413회의 비교만 수행하였다.

따라서 탐색 과정만 비교하면 BST가 순차 탐색보다

```text
4,813 - 413 = 4,400회
```

적은 숫자 비교를 수행하였다.

평균 비교 횟수도 순차 탐색은 96.26회인 반면 BST는 8.26회였다.

이번 실험에서는 탐색 키 50개 중 실제 데이터에 존재하는 값이 4개뿐이었다.
따라서 순차 탐색의 경우 실패한 탐색 대부분에서 배열의 100개 원소를 끝까지
확인해야 했고, 그 결과 평균 비교 횟수가 100에 가까운 96.26회가 되었다.

반면 BST는 탐색에 실패하더라도 루트에서 시작하여 값의 크기에 따라
왼쪽 또는 오른쪽 서브트리 중 한쪽만 따라가므로 모든 노드를 확인할 필요가 없다.
이 때문에 실패 탐색이 많았음에도 평균 8.26회의 비교만으로 탐색을 종료할 수 있었다.

## 3. BST 생성 비용을 고려한 분석

BST는 배열과 달리 데이터를 단순히 차례대로 저장할 수 없다.
새로운 값을 삽입할 때마다 루트부터 적절한 위치까지 이동하면서
기존 노드와 값을 비교해야 한다.

이번 실험에서는 BST를 생성하는 데 총 612회의 비교가 발생하였다.

따라서 BST의 실제 비용을 생성과 탐색을 합쳐 계산하면 다음과 같다.

```text
BST 생성 비용       = 612회
BST 50회 탐색 비용  = 413회
--------------------------------
총 비용              = 1,025회
```

순차 탐색은 별도의 트리 생성 과정이 필요하지 않으므로 50회의 탐색 비용인
4,813회를 기준으로 비교할 수 있다.

```text
순차 탐색 총 비용         = 4,813회
BST 생성 + 탐색 총 비용   = 1,025회
차이                      = 3,788회
```

즉 이번 실험에서는 BST를 만드는 비용까지 포함하더라도
BST 쪽이 3,788회 적은 비교를 수행하였다.

BST는 처음 생성할 때 612회의 추가 비용이 필요했지만,
그 이후 각 탐색에서 절약되는 비교 횟수가 매우 컸기 때문에
50회의 탐색을 수행하는 동안 초기 생성 비용을 충분히 회수하였다.

따라서 동일한 데이터에 대해 탐색을 여러 번 수행해야 하는 상황에서는
BST를 미리 구성하는 것이 유리할 수 있다.

반대로 탐색을 한두 번만 수행하고 데이터를 다시 사용하지 않는 경우라면
BST를 구성하는 초기 비용까지 고려했을 때 반드시 BST가 더 효율적이라고
단정할 수는 없다.

## 4. BST 구조에 따른 탐색 성능 차이

BST의 성능은 단순히 노드 개수만으로 결정되지 않고
트리의 높이와 균형 상태에 크게 영향을 받는다.

### 비교적 균형이 좋은 경우

트리가 균형에 가까우면 한 번 비교할 때마다 탐색해야 할 후보 영역을
크게 줄일 수 있다.

이 경우 탐색의 시간 복잡도는 평균적으로 다음과 같이 볼 수 있다.

```text
O(log n)
```

노드가 100개라면 완전히 균형 잡힌 트리의 높이는 대략 `log2(100)` 수준이므로,
모든 100개 원소를 확인하는 순차 탐색보다 훨씬 적은 노드만 방문할 수 있다.

### 한쪽으로 치우친 경우

예를 들어 다음처럼 정렬된 데이터를 순서대로 삽입한다고 가정할 수 있다.

```text
10, 20, 30, 40, 50, 60, ...
```

일반 BST에서는 모든 새 노드가 계속 오른쪽 자식으로 연결되어
트리가 연결 리스트와 비슷한 형태가 될 수 있다.

이 경우 트리 높이가 노드 수에 가까워지고 탐색 시간 복잡도도

```text
O(n)
```

까지 나빠질 수 있다.

따라서 일반 BST는 평균적으로 빠른 탐색 성능을 기대할 수 있지만
항상 `O(log n)`을 보장하는 것은 아니다.

AVL Tree나 Red-Black Tree와 같은 균형 이진 탐색 트리는
삽입과 삭제 후에도 높이가 지나치게 증가하지 않도록 조정하기 때문에
탐색 성능을 더 안정적으로 유지할 수 있다.

## 5. 결론

이번 실험에서는 동일한 100개의 정수를 배열과 BST에 저장하고,
동일한 50개의 탐색 키를 사용하여 숫자 비교 횟수를 직접 측정하였다.

실험 결과 순차 탐색은 총 4,813회, 평균 96.26회의 비교가 필요했고,
BST 탐색은 총 413회, 평균 8.26회의 비교가 필요했다.

BST를 생성하기 위한 612회의 비교까지 포함해도 전체 비용은 1,025회로,
순차 탐색의 4,813회보다 작았다.

이번 결과에서 BST가 큰 차이로 유리했던 주된 이유는
순차 탐색은 탐색 실패 시 항상 100개의 원소를 전부 확인해야 하지만,
BST는 트리 구조를 이용하여 탐색할 필요가 없는 영역을 제외할 수 있기 때문이다.

다만 BST의 탐색 성능은 트리의 구조에 따라 달라지며,
트리가 한쪽으로 심하게 치우친 경우에는 순차 탐색과 비슷한 수준까지
성능이 저하될 수 있다.

따라서 BST는 초기 생성 비용이 존재하지만,
트리가 적절한 구조를 유지하고 같은 데이터에 대해 탐색을 여러 번 수행하는 경우
순차 탐색보다 훨씬 효율적인 탐색 방법이 될 수 있다.
